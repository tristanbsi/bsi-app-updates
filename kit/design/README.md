# The BSI design system

One look for ShopCall, StandBy, PatchMap and Loader. Each app keeps its own hue, everything else is shared: the
surfaces, the type, the spacing, the buttons, the status colours, the tape colours, the motion. ShopCall's
`docs/ui-standards.md` is the parent of this document (it is the most worked-out of the four); where they disagree,
ShopCall's rules win for ShopCall and this document wins for the desktop apps.

Files here:

| File | What it is | Who reads it |
| --- | --- | --- |
| `tokens.json` | every value, once | scripts that draw (Loader's canvas and SVG, StandBy's dynamic styles), the tests |
| `tokens.css` | the same values as CSS custom properties, `--bsi-*` (generated by `tools/build-tokens.js`) | every stylesheet |
| `base.css` | buttons, fields, dialogs, toasts, banners, badges, tape, tables, focus, motion, on the tokens | any page that adopts by class |
| `gallery.html` | every component in all four hues, light and dark | Tristan, and anyone checking a change |

`node tools/sync-kit.js` copies `tokens.css` and `base.css` into each app as `bsi-tokens.css` and `bsi-base.css`,
next to the feedback window and next to the manual. `npm test` in this repo checks contrast and that the CSS matches
the JSON.

## Principles

1. **One lit surface per screen.** The thing being worked on (the gig being prepped, the live cue, the selected
   case) sits on `--bsi-bg-lit`. Everything else is type on the floor, separated by space and hairlines, or a quiet
   well (`--bsi-bg-raised`). Never a box around every section, never a coloured side stripe.
2. **Sentence case.** Headings, buttons, labels, tabs. Tracked capitals survive only on mono state codes
   (`RELEASED`, `ORDER CHANGED`) because those are scanned like IDs.
3. **Colour means status, done, or identity.** Green = ok, amber = attention, red = stop, teal = done (a moment,
   never a list). Tape hues = gig identity. The app's accent = links, focus, the one primary button, selection.
   Nothing else is coloured. A page must still read in greyscale: every colour has a word or a shape beside it.
4. **Calm by default.** A quiet state looks intentional. Empty states are one line, not an empty panel. Motion is
   short and never carries meaning on its own.
5. **Phone-first where a phone is used** (ShopCall's tech views, StandBy's follow screen). 44 px touch targets,
   one column, the run-sheet order. Desktop apps are dense scanning surfaces and stay at the desktop sizes.
6. **Plain words.** Buttons say what happens ("Start pull", "Remove port"), never "OK" or "Submit". Errors say what
   to do next. Tristan's crew are not software people.

## Type

Font: **Montserrat** for UI text, **IBM Plex Mono** for counts, IDs, times and codes, tabular figures. Montserrat
is the brand face (ShopCall and StandBy already use it). PatchMap (IBM Plex Sans) and Loader (Barlow) each ship
their own face today; the proposal is that both move to Montserrat in their next design round so the suite reads as
one family. Until then they set `--bsi-font-sans` in their own stylesheet.

| Token | Size | Weight | Use |
| --- | --- | --- | --- |
| `--bsi-t-display` | 28 | 600 | the one big name on a screen (a gig, a show) |
| `--bsi-t-title` | 22 | 600 | a screen title on a phone |
| `--bsi-t-section` | 19 | 700 | a section heading; outranks everything inside its well |
| `--bsi-t-item` | 17 | 600 | an item inside a section (a gig row, a dialog title) |
| `--bsi-t-heading` | 15 | 600 | a sub-heading, a progress sentence ("38 of 52 pulled") |
| `--bsi-t-body` | 14 (ShopCall 13.5) | 400 | body |
| `--bsi-t-meta` | 12 | 400 | dates, stamps, hints, badges |

Line height 1.5 for body, 1.25 for headings. Nothing outside the scale: no 32 px stat numerals, no 10 px labels.
Progress reads as a sentence with mono counts, never a stat tile. Dates: `Thu Sep 17`, `today`, `in 2 days`;
times 24 h `15:02`.

## Spacing, radii, the chamfer

Spacing scale: 4 · 8 · 12 · 16 · 24 · 32 · 48 (`--bsi-space-1` to `-7`). A section gap is at least twice a row's
padding. Hairlines are 1 px and inset to the card padding.

Radii: `--bsi-radius` 4 px for cards and tags, `--bsi-radius-control` 6 px for buttons and fields,
`--bsi-radius-well` 10 px for section wells and dialogs, `--bsi-radius-pill` for pills and switches.

**The chamfer rule.** ShopCall's write buttons cut two corners (`--bsi-chamfer` 7 px) and draw their edge as a
line of light in the page's own colour: a button is part of the page's frame, so it wears the frame's hue. That
only makes sense where a page has a frame hue, which is ShopCall. The desktop apps use the round 6 px button with
the same hierarchy and the same sizes. Both are "the BSI button": same height, same weights, same focus ring,
same hover and pressed behaviour. Phone-only round controls (the refresh button in a phone header) stay round.

## Buttons

| Class | Use | Rule |
| --- | --- | --- |
| `.bsi-btn-primary` | the one action the screen is for | one per screen; the app's accent fill |
| `.bsi-btn` (secondary) | other actions | outlined, neutral |
| `.bsi-btn-quiet` | navigation, Cancel, "what's this?" | text only, no box |
| `.bsi-btn-warn` | an armed action that changes state (un-pull, mark short) | amber fill; attention is never the page colour |
| `.bsi-btn-danger` | destructive (delete, remove) | red fill, or `.outline` for a red-edged Remove… that asks first |

Sizes: 32 px default, `.bsi-btn-sm` 26 px (in table rows and toasts), `.bsi-btn-lg` 44 px (phone primaries; on a
coarse pointer every button grows to 44). Busy = `.busy` or `disabled`: 45 % opacity, no light, no motion.
Order in a row: secondary actions first, the primary last (rightmost). Labels are verbs in sentence case.

## Fields

`.bsi-field` for text, number, select and textarea. 32 px tall, raised surface, strong hairline, 6 px radius,
placeholder in faint. Label above in meta size and muted (`.bsi-label`), help below (`.bsi-help`), error below in
red words (`.bsi-error`) with `aria-invalid` on the field: never a red glow alone. Numbers use `.mono`.
Checkbox `.bsi-check`, switch `.bsi-switch` (accent when on), segmented control `.bsi-seg` (accent fill on the
chosen segment). Forms validate on submit, in words, next to the field.

## Dialogs

`dialog.bsi-dialog`: raised surface, 10 px radius, a scrim behind. Title at the item size (a question in plain
words: "Remove this port?"), body sentences with the consequence and the way back ("Undo brings everything
back"), then actions right-aligned with the safe one first and the primary or danger last. Escape and the scrim
close it as Cancel. Focus goes to the first field or the safe button and returns to what opened it. One dialog at
a time; never a dialog to say "saved".

## Toasts and banners

A **toast** (`.bsi-toast`) is a result: bottom centre, one line, optional one action (Undo), drains over
`--bsi-drain-toast` (8 s) with a thin bar and leaves. Hover pauses the drain. Kinds: neutral, `.ok`, `.warn`,
`.danger`.

A **banner** (`.bsi-banner`) is a state: in the flow at the top of what it is about, stays until the state is
untrue (host lost, order changed, stale data). Kinds `.info` (accent edge), `.ok`, `.warn`, `.danger` (the kind's
colour on the bold lead word and the edge; the body stays in normal text). A banner that resolves itself gets
`.drain` and `--bsi-drain` (StandBy's green caller banners drain in 8 s, its amber crash notice in 20 s, caller
messages in 60 s). Errors never use a modal; they use a danger banner with the next step.

## Status marks

Status is **a filled mark and a word**, never an edge. `.bsi-dot.warn` is round; `.bsi-dot.danger` is a square
turned 45°, so red and amber differ by shape as well as hue. `.bsi-badge` is the mono uppercase state code
(neutral unless the state is warn / danger / done / ok). Text-only status uses `.bsi-ok`, `.bsi-warn`,
`.bsi-danger`, `.bsi-done`. Done teal marks moments (a completed pull, "Nothing needs you"), never a column of
identical badges.

Values (all pass 4.5:1 on base, raised and lit surfaces in their theme):

| Role | Light | Dark |
| --- | --- | --- |
| ok | `#187A49` | `#4FC38A` |
| warn | `#8F5A00` | `#F2A93B` |
| danger | `#C2372F` | `#F27A72` |
| done | `#157468` | `#3BC0AE` |

StandBy's cue states (Live green, Standby amber, GO, over/late red, changed cyan, rehearsal violet) are StandBy's
own domain tokens layered on top of these; they keep their meanings from `proposal.md`.

## Tape

The shop's tape stock, the same in every app and theme, always a straight-edged shape (a 10 px square before a
name, or a solid tag that names the tape: "Blue tape"). Screen representations, not colour matches: red, yellow
and orange are pulled toward brick, mustard and a truer orange so they sit apart from danger and warn.

Red `#B8372E` · Yellow `#C9A227` · Blue `#3F8FD2` · Green `#3FAE7A` · Orange `#D8731F` · Purple `#8E63D6` ·
Black `#2B2F36` (with a grey outline so it exists on near-black) · White `#E6E8EB` (with a hairline). Tag text is
light on red and black and dark on everything else (light text failed AA on blue and purple). The tape is always
named in words somewhere on the card for anyone who cannot tell the hues apart. One tape mark per place: no bands,
no stripes.

## The BSI mark

`bsi-mark-white.png` (in ShopCall's `design/brand/`) at 38 × 26 in a header, or the black mark on light. Never
recoloured, stretched, cropped or given effects. The brand is black; there is no brand accent, which is why each
app has its own.

## Light and dark

Light is the base in the CSS; dark follows the Mac (`prefers-color-scheme`) unless `data-theme="light|dark"` on
`<html>` says otherwise. Both themes use the same roles with the same meanings. The neutral surfaces are shared:

| Role | Light | Dark |
| --- | --- | --- |
| bg-base / raised / sunken / lit | `#F4F5F6` / `#FFFFFF` / `#E9EBEE` / `#FFFFFF` | `#0A0B0D` / `#15171B` / `#050607` / `#2F3135` |
| fg / muted / faint | `#17191C` / `#4E545C` / `#646A73` | `#F1F2F3` / `#A9AFB6` / `#7D848C` |
| border / strong / lit | `#D9DCE1` / `#C3C8CF` / `#C3C8CF` | `#22262B` / `#30353C` / `#44474C` |

Faint is for glyphs, not sentences. Dark is the canonical theme for ShopCall ("a stage with the house lights
down") and StandBy (dim control rooms); PatchMap and Loader follow the Mac.

## Per-app identity

Set `data-app` on `<html>` (or any ancestor). It changes the accent tokens and nothing else, except StandBy,
whose warmth is part of its look.

| App | Accent (light / dark) | On accent | Notes |
| --- | --- | --- | --- |
| ShopCall | `#2F6FA8` / `#7FB4EA` | white / near-black | the Mineral page hues (sandstone, lapis, coral, …) stay in the Hub's `Themes.html`; they colour the frame only |
| StandBy | gold `#E0AD2E` / `#F0C75E`, text-gold `#8A6200` on light | `#1D1A17` | surfaces warm: `#141210` base, `#1C1916` raised, `#26221E` lit; light `#F7F5F2` |
| PatchMap | teal `#1A7A72` / `#3FB3A7` | white / `#0F1A18` | light teal darkened one step from today's `#1E8C82` so white text on it passes AA |
| Loader | orange `#B5540F` / `#F0924A` | white / `#1B1206` | light orange darkened one step from today's `#C8601A` for the same reason |

Proposal: keep all four. They are already the hues the crew knows each app by. The two light-mode darkenings are
the only value changes to an app's identity.

## Icons

Inline SVG on a 16 px grid, 1.7 px stroke, round caps and joins, `currentColor`, no fills. `.bsi-icon`. An
icon never appears without a word next to it unless the button has an `aria-label`.

## Motion

`--bsi-dur-fast` 120 ms for hover and press, `--bsi-dur-base` 160 ms for state changes, `--bsi-dur-slow` 300 ms
for something arriving or leaving; easing `cubic-bezier(.2, .7, .2, 1)`. A change flash is one brightening that
settles (StandBy's GO lands). `prefers-reduced-motion` turns every duration to zero; nothing may carry meaning by
motion alone.

## Adopting it in an app

1. `node tools/sync-kit.js` puts `bsi-tokens.css` and `bsi-base.css` in the app.
2. Link both, put `class="bsi" data-app="<id>"` on `<html>`.
3. Map the app's existing variables onto the tokens in one block (for example `--ink: var(--bsi-fg);
   --panel: var(--bsi-bg-raised); --accent: var(--bsi-accent);`) so nothing has to be rewritten at once.
4. New components use the `.bsi-*` classes; old ones move over when touched.
5. The feedback window and the manual's What's new already use the tokens, so they look the same in every app.

## Cohesion checklist

Run this on every screen before it ships.

- [ ] One lit surface, or none; sections are wells or type on the floor; no coloured edges or stripes.
- [ ] Every heading in sentence case; capitals only on mono state codes.
- [ ] Type sizes from the scale only; counts, IDs and times in mono with tabular figures.
- [ ] One primary button, verbs on every button, the primary last in its row, 44 px on phones.
- [ ] Colour appears only as status (green / amber / red / teal), tape, or the app's accent on links, focus and the primary.
- [ ] Every status colour has a word or a shape beside it; warn round, danger a diamond; readable in greyscale.
- [ ] Text passes AA on its surface (faint only on glyphs); the gallery's swatches are the reference.
- [ ] Dialogs ask a plain question, say the consequence and the way back, Escape cancels, focus returns.
- [ ] Results are toasts that drain; states are banners that stay; errors say the next step; no modal for "saved".
- [ ] Empty and quiet states are one line and look intentional; loading and failed states exist for every server call.
- [ ] The page says how old its data is when it can go stale.
- [ ] Dark and light both checked; the app's identity hue is on `data-app`, nothing hard-coded.
- [ ] Motion is short, from the tokens, and off under reduced motion.
- [ ] The BSI mark is unaltered; the app's own name and icon carry the identity.
